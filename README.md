# 五牌密码 · Five-Card Code

一个把 **Fitch Cheney 五张牌魔术**（1930s）做成的网页小游戏。纯前端、单文件、离线可玩。

## 打开

双击 `index.html` 即可，无需服务器、无需联网。

## 三个模式

| 模式 | 你在做什么 |
| --- | --- |
| **当魔术师** | 看助手摆出的四张牌，说出扣着的第五张。新手模式会标出「第一张定花色」并给出排列提示。 |
| **当助手** | 反过来：你决定藏哪张、按什么顺序亮牌，由程序扮演魔术师来读你的密码，并告诉你读错在哪一步。 |
| **解密手册** | 三条规则、六种排列对照表、一个逐步拆解的例子。 |

右上角「对照表」随时弹出六种排列的口袋速查卡。成绩（命中数 / 连胜 / 最佳连胜）存在 `localStorage`，关掉页面也不丢。

## 数据存在哪

只有一处：浏览器 `localStorage`，键名 **`five-card-code.v1`**，值是一段 JSON：

```json
{
  "beginner": true,
  "stats": {
    "magician": { "rounds": 4, "correct": 4, "streak": 4, "best": 4 },
    "assistant": { "rounds": 2, "correct": 2 }
  }
}
```

查看 / 手动清除：DevTools → Application → Local Storage → 当前站点 → `five-card-code.v1`。
界面上的清除入口是首页统计条右侧的「清除战绩」：**点两次**才生效（第一次变成「再点一次确认」，4 秒内不点会自动复原），清完会短暂显示「已清除」。只清数字，不动「新手提示」开关。

### 部署到服务器后，新设备是独立数据吗

是，而且不需要改任何代码。`localStorage` 按**来源（origin）隔离**，也就是「协议 + 域名 + 端口」；它存在访客自己的浏览器里，不经过服务器。所以：

- 换一台电脑 / 换一个浏览器 / 换一个手机 → 打开就是 `0 / 0`，互不影响；
- 同一个域名下所有访客各存各的，服务器上没有任何战绩数据；
- 换域名或换端口（如 `http://localhost:8000` → `https://example.com`）→ 会被当成新的来源，战绩不继承；
- 无痕窗口关掉即清空；清理浏览器数据也会丢。

如果确实需要「换设备也能接着看」，那就必须加后端：账号体系 + 一个 `GET/POST /api/stats` 接口，登录后用接口数据覆盖本地值。当前版本刻意没有做，保持纯静态、零后端。

## 本地发布

```bash
# 任选其一
python -m http.server 8000
npx serve .
```

然后访问 `http://localhost:8000`。注意：用 `file://` 直接打开时，各浏览器对本地文件的存储策略略有差异；挂到 http(s) 后就严格按「域名 + 端口」隔离。

## 密码的三条规则

1. **花色**：5 张牌只有 4 种花色，必有两张同花色（鸽巢原理）→ 第一张牌报花色。
2. **步数**：把 A~K 看成 1~13 的环，同花色两张牌总有一个方向距离 ≤ 6 → 从第一张往后数 1~6 步就是藏牌。
3. **数字**：剩下 3 张牌有 3! = 6 种排列，正好编码 1~6 → 读出排列就知道数几步。

点数相同时按 ♠ ♥ ♦ ♣ 排序（代码与界面使用的是同一套比较器）。

## 文件

- `index.html` — 整个游戏：样式、规则引擎、界面逻辑都在里面。
- `verify.js` — 穷举验证脚本（Node 运行，不需要依赖）。

## 验证

```bash
node verify.js
```

它从 `index.html` 里抽出引擎，对 **全部 C(52,5) = 2,598,960 手牌**逐一验证：

- 每手牌都存在合法编码；
- 每种编码（共 6,115,200 种）解码后都等于被藏起的那张牌；
- 亮出的四张互不重复、且不含藏牌；
- 任意乱序摆法下，`diagnose` 的判定与 `decode` 的结论一致。

输出示例：

```
✓ 穷举完成：2,598,960 手牌 / 6,115,200 种编码，用时 32.3s
✓ 任意摆法一致性：30000 次中 28528 次被拒，异常 0 次
✓ 正确摆法检测：30000/30000 次判定成功
全部通过 ✅
```

也就是说：这个魔术在这副牌上是**必然成功**的，不是概率。
